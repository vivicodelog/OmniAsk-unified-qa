# 设计文档：文档+数据统一问答平台

## 决策背景

**2026-08-07**：用户脱产转 AI 求职，投简历半个月反馈不理想，需要一个面试竞争力强的项目。

## 选型过程

评估了 3 个方向：

| 方案 | 面试竞争力 | 编码深度 | 可行性 |
|------|-----------|---------|--------|
| 文档+数据统一问答 ✅ | 最高 | 中高 | 中 |
| 纯多模态文档 | 中 | 最高 | 中 |
| AI 代码审查 | 低 | 最高 | 低 |

**选方案 1**：场景冲击力最强（"什么文件都能传、什么问题都能答"），复用现有 NL2SQL/Agent 积累。

## 硬件约束
- 无 GPU，32G 内存，i7-13700H
- 无梯子，全部国内服务
- Windows 11 + Git Bash

## 技术选型及原因

| 组件 | 选型 | 为什么 |
|------|------|--------|
| 文本 LLM | DeepSeek API | 国内直连，便宜，代码能力好 |
| 多模态 LLM | Qwen-VL API（阿里云百炼） | 国内直连，不本地部署 |
| 文本 Embedding | BGE-M3 本地 CPU | 已验证，ModelScope 国内下载 |
| PDF 解析 | PyMuPDF + pdfplumber | 表格检测 pdfplumber 强，图片提取 PyMuPDF |
| SQL 校验 | 正则 + sqlite3 自带 AST | 不需要额外依赖 |
| 图表选择 | 启发式规则为主，LLM 兜底 | 确定性优先，规则能覆盖 80% 场景 |

## 分阶段交付

### v1（8 天）：数据分析助手
上传 Excel/CSV → 列类型推断 → SQLite 临时表 → NL2SQL → SQLGuard → 查询执行 → ChartSelector → 图表+结论

### v2（10 天）：多模态文档理解
上传 PDF → PyMuPDF 解析（文本/表格/图片+坐标）→ BGE-M3 文本检索 → 图文关联 → Qwen-VL 看图回答 → 前端 PDF 预览+高亮定位

### 打通（2 天）
FileRouter 统一入口 → 自动识别文件类型 → 分派链路 → 统一对话面板

## 编码重点（手写核心代码）

| 模块 | 估计行数 | 技术点 |
|------|---------|--------|
| excel_parser.py | ~250 | 列类型推断、多 sheet、合并单元格处理 |
| pdf_parser.py | ~400 | 文本/表格/图片提取、坐标记录 |
| sql_guard.py | ~120 | 正则+AST 双重校验 |
| chart_selector.py | ~300 | 启发式规则引擎 |
| file_router.py | ~150 | MIME 检测+策略模式分派 |
| fusion.py | ~250 | 文本检索+图文关联 |
| 前端 PDF 高亮组件 | ~350 | vue-pdf-embed + Canvas 覆盖层 |
| 前端图表+对话面板 | ~400 | ECharts + SSE 流式 |

## 协作模式
- 拆 → 写 → 验 → 复盘，每个模块四步走
- pytest 测试先行，关键模块必测
- 每天一个可测试增量，不攒到第二天
- 每个模块完成时提供面试追问清单
